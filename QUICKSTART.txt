BOOKING CRM v7 — Python 3.11+ recommended

INSTALL
python -m pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000

Defaults: /admin admin123; /admin/outbound 123123. Change production passwords!
Configure ADMIN_PASSWORD, OUTBOUND_PASSWORD, SESSION_SECRET, BASE_URL and DATA_DIR
as environment variables. .env.example is a template, NOT automatically loaded;
uvicorn --env-file .env may be used if python-dotenv is installed.

UPGRADE FROM v6
Back up salon.db (use SQLite backup API or stop the server before copying DB/WAL).
Use the SAME existing DATA_DIR; do not delete or replace the database.
New tables and new settings are created on startup. Existing rows are preserved.
Keep an existing SESSION_SECRET; otherwise a private persistent key is created in
DATA_DIR/.session-secret. Keep this file with the DB to retain review-link validity.
Use a persistent volume for DATA_DIR and keep uploads on persistent storage too.
For container deployments mount static/uploads or persist that directory separately.
Set a real HTTPS BASE_URL for CORS. Share the actual public domain, not localhost.

NEW FLOWS
1. Set business niche in Settings. Configure actual services/prices/durations.
   Real quiz quotes use active services in that niche, not demo service prices.
   Car goals are mapped by name when possible, otherwise the available catalog.
   Add-on tariffs live in growth.py / ADDONS (PLN); each has a real 20% bundle
   discount and extra duration. Size multipliers are defined in quote_package.
   Quotes are signed and expire after 30 minutes. Client-supplied price is ignored.
   Package price and duration are saved in the booking; overlap checks use duration.
2. Mark a real booking Completed. The row offers Send review link: WhatsApp,
   Telegram share, or Copy. Review URLs contain a non-guessable signature.
   Feedback -> private issues, positive ratings, resolution and failed-alert retry.
   Google Maps is accessible at ANY rating when its review URL is configured.
   No fake positive review is prefilled; customers write their own words.
   Review gating/selective positive solicitation is intentionally not implemented.
3. Connect Telegram token and owner Chat ID, /start the bot, then enable the
   daily summary. Default time 21:00, default timezone Europe/Warsaw (configurable).
   Automatic delivery is OFF until enabled. Summary uses Completed only for revenue;
   Cancelled and NoShow are counted separately. Mixed currencies use current FX;
   FX date is shown, including fallback when offline. This is not accounting data.
   The Dashboard test button actually calls Telegram; it does NOT fake success.
4. ?demo=1 -> quiz, feedback sandbox, or fictional report in one tap.
   /feedback/demo never stores feedback or notifies anyone.
   The public report preview is fictional; real test sending requires admin auth.
   Load sample data creates 4 fictional completed bookings and 4 ratings:
   2, 5, 5, 3. Marked DEMO and excluded from real daily reports. Import is idempotent.

SCHEDULING / OPERATIONS
One deployment = one business (not a multi-tenant platform).
The asyncio scheduler runs inside the application, checking every 30 seconds.
Keep the process always on; sleeping/serverless hosts cannot deliver on time.
The persistent SQLite delivery ledger prevents normal duplicate daily sends across
workers/restarts. Failed sends retry up to three times with a five-minute backoff.
An external send cannot be made exactly-once across a crash between Telegram
accepting it and recording success; rare duplicate delivery remains possible.
Missed time is caught up on the same business day after restart, not prior days.
Business appointment times are local-naive; Feedback.created_at is UTC, and
review/report day boundaries respect the configured IANA business timezone.
Legacy v6 customer lookup by phone is retained; add OTP verification before using
that lookup for sensitive customer histories. The public demo never reads them.
